## 1. 触ってよい範囲

- **`demo/` の中だけ。** 依頼への対応で `demo/` の外（ワークフロー・スクリプト・プロンプト・docs）を変えない
- `demo/index.html` は1ファイルで完結している。文言・色・並び・表の中身はここで直る
- 画像は使っていない。画像の追加が要る依頼は `要ローカル`

## 2. 対応案の粒度

- 「どのページの、どこを、どう変えるか」が1行で言えるものは、そのまま対応案にする
- 複数の変更が混ざった依頼は、②の箇条書きで分けて書く（3つまで。超えるなら分割を提案）
- デザインの好みが分かれる変更（色・余白・フォント）は、③で選択肢を出す

## 3. 要ローカル（この環境ではやらない）

- 画像・動画の追加や差し替え
- 外部サービス（解析・フォーム送信先など）の設定変更
- 実機での見え方の確認が結論に要るもの

## 4. 確認用ページ

- 作業ブランチ `issue-<番号>` を push すると `https://kenhomma.github.io/idd/preview/issue-<番号>/` に出る
- 画面の右下に「版: issue-<番号>」と出るので、どの版を見ているかはそこで分かる
- 本番は `https://kenhomma.github.io/idd/`（右下は「版: main」）
